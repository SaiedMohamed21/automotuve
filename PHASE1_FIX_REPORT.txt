4. MOCK SEED DATA FALLBACK PREVENTION
--------------------------------------------------------------------------------
- Business data initial states are set to empty arrays [] or maps {}.
- If an API request fails (e.g. 401 or 403), loadBackendData sets the target dataset to [] (not SEED_*) and records the error in backendLoadErrors.
- Failed requests are distinguishable from "0 database records" via recorded backendLoadErrors and explicit console logs.


--------------------------------------------------------------------------------
5. API FAILURE REPRESENTATION
--------------------------------------------------------------------------------
- Promise.allSettled tracks each endpoint status (fulfilled vs rejected).
- Rejected requests set state to [] and store the failure reason (e.g. backendLoadErrors.parts = "HTTP 403 Forbidden").
- Accountant logins receive 403 on GET /api/warehouse/parts, resulting in wParts = [] and backendLoadErrors.parts populated, preventing Accountant users from seeing fake SEED_PARTS.


--------------------------------------------------------------------------------
6. DUPLICATE LOADING PREVENTION
--------------------------------------------------------------------------------
- isDataLoadingRef (useRef(false)) guards loadBackendData() against concurrent re-entry.
- loadBackendData is wrapped in useCallback and called intentionally only on:
  1. Validated initial startup.
  2. Post-login submission via handleLoginSuccess.

7. LOGOUT BEHAVIOR

- Clicking Sign Out (handleSignOut) removes the JWT token from localStorage, resets role/user state, and flushes all sensitive backend business arrays to [], preventing residual data from remaining visible between user sessions.
